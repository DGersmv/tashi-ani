# 🔧 Исправление проблемы: Приложение перестает работать через время

## Проблема
Через некоторое время после запуска приложение перестает отвечать на запросы. После перезапуска PM2 всё снова работает.

## ✅ Решения

### Решение 1: Улучшить конфигурацию PM2 (УЖЕ СДЕЛАНО)

Конфигурация `ecosystem.config.js` обновлена с улучшенными настройками:
- Автоматический перезапуск при ошибках
- Мониторинг памяти
- Задержки перед перезапуском
- Проверка готовности приложения

**Примените изменения:**

```bash
cd /var/www/tashi-ani

# Перезапустите с новой конфигурацией
pm2 delete tashi-ani
pm2 start ecosystem.config.js
pm2 save
```

### Решение 2: Настроить автоматический мониторинг

**Сделайте скрипт исполняемым:**

```bash
chmod +x scripts/monitor-app.sh
```

**Добавьте в cron для проверки каждые 5 минут:**

```bash
crontab -e
```

Добавьте строку:
```
*/5 * * * * /var/www/tashi-ani/scripts/monitor-app.sh
```

### Решение 3: Проверить логи на ошибки

```bash
# Посмотрите логи на ошибки
pm2 logs tashi-ani --lines 200 --err

# Или проверьте файлы логов
tail -100 /var/www/tashi-ani/logs/err.log
tail -100 /var/www/tashi-ani/logs/combined.log
```

### Решение 4: Проверить использование памяти

```bash
# Проверьте текущее использование памяти
pm2 monit

# Или
pm2 status
```

### Решение 5: Настроить автоматический перезапуск по расписанию

Если проблема повторяется регулярно, можно настроить перезапуск по расписанию:

```bash
crontab -e
```

Добавьте строку для перезапуска каждую ночь в 3:00:
```
0 3 * * * pm2 restart tashi-ani
```

### Решение 6: Проверить базу данных на блокировки

Если проблема связана с базой данных:

```bash
# Проверьте размер базы данных
ls -lh prisma/prod.db

# Проверьте блокировки (если используете SQLite)
sqlite3 prisma/prod.db "PRAGMA integrity_check;"
```

### Решение 7: Увеличить лимит памяти (если нужно)

Если сервер имеет больше памяти, можно увеличить лимит:

```bash
nano ecosystem.config.js
```

Измените:
```javascript
max_memory_restart: '1.5G', // или '2G'
```

Затем:
```bash
pm2 restart tashi-ani
```

## 🔍 Диагностика

### Проверьте, что происходит при падении:

```bash
# Включите детальное логирование
pm2 logs tashi-ani --lines 0 --raw

# Оставьте работать и следите за логами
# Когда приложение перестанет работать, посмотрите последние строки
```

### Проверьте системные ресурсы:

```bash
# Проверьте использование памяти системы
free -h

# Проверьте использование диска
df -h

# Проверьте нагрузку на CPU
top
```

### Проверьте сетевые соединения:

```bash
# Проверьте, слушается ли порт 3000
netstat -tulpn | grep 3000

# Проверьте активные соединения
ss -tulpn | grep 3000
```

## 📊 Мониторинг

### Настройте PM2 мониторинг:

```bash
# Установите PM2 мониторинг (если еще не установлен)
pm2 install pm2-logrotate

# Настройте ротацию логов
pm2 set pm2-logrotate:max_size 10M
pm2 set pm2-logrotate:retain 7
pm2 set pm2-logrotate:compress true
```

### Просмотр статистики:

```bash
# Статистика использования ресурсов
pm2 monit

# Детальная информация
pm2 show tashi-ani
```

## 🆘 Если ничего не помогает

1. **Обновите код из GitHub:**
   ```bash
   cd /var/www/tashi-ani
   git pull origin master
   npm install
   npm run build
   pm2 restart tashi-ani
   ```

2. **Проверьте версии зависимостей:**
   ```bash
   npm outdated
   ```

3. **Пересоздайте базу данных:**
   ```bash
   # Сделайте бэкап
   cp prisma/prod.db prisma/prod.db.backup
   
   # Пересоздайте базу
   rm prisma/prod.db
   npx prisma migrate deploy
   ```
