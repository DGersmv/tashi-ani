# 🔧 ИСПРАВЛЕНИЕ ПРОБЛЕМЫ: 403 Forbidden через время

## 🎯 РЕАЛЬНАЯ ПРИЧИНА ПРОБЛЕМЫ

**SQLite блокирует базу данных при одновременных запросах!**

SQLite НЕ предназначен для production с несколькими одновременными запросами. Когда база заблокирована:
- Запросы зависают
- Next.js может возвращать 403 Forbidden
- После перезапуска всё работает (блокировка снимается)

## ✅ ЧТО ИСПРАВЛЕНО

1. **Добавлены таймауты для Prisma** - запросы не будут висеть бесконечно
2. **Добавлена обработка ошибок блокировки** - автоматическая повторная попытка
3. **Улучшена конфигурация Prisma** - более стабильная работа с SQLite

## 📋 ЧТО НУЖНО СДЕЛАТЬ НА СЕРВЕРЕ

### Шаг 1: Обновите код из GitHub

```bash
cd /var/www/tashi-ani

# Обновите код
git pull origin master

# Пересгенерируйте Prisma клиент (ВАЖНО!)
npx prisma generate

# Пересоберите проект
npm run build

# Перезапустите приложение
pm2 restart tashi-ani
```

### Шаг 2: Проверьте .env.local

Убедитесь, что `DATABASE_URL` указывает на правильный путь:

```bash
cat .env.local | grep DATABASE_URL
```

Должно быть:
```env
DATABASE_URL="file:./prisma/prod.db"
```

### Шаг 3: Проверьте базу данных

```bash
# Проверьте, что база существует
ls -la prisma/prod.db

# Если базы нет, создайте её
npx prisma migrate deploy
```

## 🔍 ЕСЛИ ПРОБЛЕМА ПОВТОРЯЕТСЯ

SQLite НЕ подходит для production с несколькими пользователями одновременно!

### Решение: Перейдите на PostgreSQL

PostgreSQL поддерживает одновременные запросы и не блокирует базу.

**Шаги для перехода на PostgreSQL:**

1. Установите PostgreSQL на сервере
2. Создайте базу данных
3. Обновите `DATABASE_URL` в `.env.local`
4. Примените миграции

**См. инструкцию:** `FRESH_UBUNTU_INSTALL.md` → раздел "Установка PostgreSQL"

## ⚠️ ВАЖНО

- SQLite = для разработки и малых нагрузок (1-2 пользователя)
- PostgreSQL = для production (несколько пользователей одновременно)

Если у вас больше 1 пользователя одновременно - **ОБЯЗАТЕЛЬНО используйте PostgreSQL!**
