# 🔧 Решение проблем миграции

## ❌ Проблема 1: Нет прав на создание БД

**Ошибка:** `ERROR: permission denied to create database`

**Причина:** Пользователь `admin` не имеет прав на создание новых баз данных на кластере reg.ru.

**Решения:**

### Вариант А: Использовать одну из существующих БД (рекомендуется)

На кластере reg.ru уже есть 2 базы данных. Можно использовать одну из них!

**Что нужно сделать:**

1. **Посмотреть список существующих БД:**
   ```powershell
   $env:PGPASSWORD="Gdv2210974!"
   & "C:\Program Files\PostgreSQL\17\bin\psql.exe" -h 79.174.89.232 -p 15555 -U admin -d postgres
   
   # В psql:
   \l
   # Посмотреть список баз данных
   \q
   ```

2. **Использовать одну из существующих БД:**
   - Выберите одну из существующих БД
   - Обновите `.env.local` с именем существующей БД
   - Или очистите существующую БД (если там нет важных данных)

### Вариант Б: Обратиться в поддержку reg.ru

Попросите поддержку reg.ru:
- Создать новую БД `tashi_ani_prod`
- Или выдать права пользователю `admin` на создание БД

## ❌ Проблема 2: Prisma не находит DATABASE_URL

**Ошибка:** `Environment variable not found: DATABASE_URL`

**Причина:** Prisma по умолчанию читает переменные из файла `.env`, а не из `.env.local`.

**Решения:**

### Вариант А: Создать файл `.env` (рекомендуется)

**Создать файл `.env` в корне проекта с содержимым:**

```bash
# .env
DATABASE_URL="postgresql://admin:Gdv2210974!@79.174.89.232:15555/tashi_ani_prod?sslmode=require"
```

**⚠️ ВАЖНО:**
- Замените `tashi_ani_prod` на имя существующей БД (если используете Вариант А из Проблемы 1)
- Не коммитьте `.env` в git! (должен быть в `.gitignore`)

### Вариант Б: Использовать .env.local (если поддерживается)

Некоторые версии Prisma поддерживают `.env.local`, но не все. Лучше использовать `.env`.
