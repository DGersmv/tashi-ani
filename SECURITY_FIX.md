# 🔒 Исправления безопасности

## Обнаруженные проблемы

В логах сервера обнаружены попытки эксплуатации уязвимостей (RCE - Remote Code Execution):
- Попытки выполнения команд: `boatnet.x86_64`, `yamaha.x86_64`, `broncano`
- Попытки доступа к системным файлам: `/dev/lrt`, `//lrt`
- Подозрительные ошибки: `returnNaN is not defined`, base64 строки

## Внесенные исправления

### 1. Добавлена валидация путей к файлам
- Создан модуль `src/lib/security.ts` с функциями валидации
- Добавлена защита от path traversal атак
- Валидация всех путей к файлам перед чтением

### 2. Санитизация пользовательского ввода
- Валидация и санитизация имен файлов
- Проверка email адресов
- Валидация ID объектов

### 3. Логирование подозрительной активности
- Все подозрительные запросы логируются с меткой `[SECURITY ALERT]`
- Логирование IP адресов и User-Agent
- Отслеживание попыток path traversal

## Обновленные файлы

1. `src/lib/security.ts` - новый модуль безопасности
2. `src/app/api/uploads/objects/[id]/[filename]/route.ts` - добавлена валидация
3. `src/app/api/uploads/objects/[id]/panoramas/[filename]/route.ts` - добавлена валидация

## Рекомендации по безопасности сервера

### 1. Проверьте логи nginx/apache
```bash
# Проверьте логи доступа
sudo tail -n 1000 /var/log/nginx/access.log | grep -E "(boatnet|yamaha|broncano|lrt|returnNaN)"

# Проверьте логи ошибок
sudo tail -n 1000 /var/log/nginx/error.log
```

### 2. Проверьте активные процессы
```bash
# Проверьте, нет ли подозрительных процессов
ps aux | grep -E "(boatnet|yamaha|broncano)"

# Проверьте сетевые соединения
netstat -tulpn | grep -E "(50\.6\.248\.160|suspicious_ip)"
```

### 3. Проверьте файловую систему
```bash
# Проверьте, нет ли подозрительных файлов
find /var/www/tashi-ani -name "*.x86_64" -o -name "*boatnet*" -o -name "*yamaha*"

# Проверьте права доступа
ls -la /var/www/tashi-ani/public/uploads/
```

### 4. Настройте firewall
```bash
# Заблокируйте подозрительные IP адреса
sudo ufw deny from 50.6.248.160

# Или используйте fail2ban
sudo apt-get install fail2ban
```

### 5. Обновите зависимости
```bash
cd /var/www/tashi-ani
npm audit
npm audit fix
```

### 6. Проверьте переменные окружения
```bash
# Убедитесь, что секретные ключи не раскрыты
cat .env | grep -E "(SECRET|KEY|PASSWORD)"
```

### 7. Настройте rate limiting
Рекомендуется добавить rate limiting для API endpoints через nginx или middleware.

### 8. Мониторинг
Настройте мониторинг подозрительной активности:
- Отслеживайте `[SECURITY ALERT]` в логах PM2
- Настройте алерты на подозрительные паттерны

## Дополнительные меры безопасности

1. **Регулярные обновления**: Обновляйте систему и зависимости регулярно
2. **Мониторинг**: Настройте автоматический мониторинг логов
3. **Backup**: Регулярно создавайте резервные копии
4. **Аудит**: Регулярно проверяйте логи на подозрительную активность

## Что делать при обнаружении атаки

1. **Немедленно**: Проверьте логи и определите источник атаки
2. **Заблокируйте**: Заблокируйте подозрительные IP адреса
3. **Проверьте**: Убедитесь, что система не скомпрометирована
4. **Обновите**: Обновите код с последними исправлениями безопасности
5. **Сообщите**: Если обнаружена серьезная уязвимость, сообщите команде

## Проверка после обновления

После деплоя обновлений проверьте:

```bash
# 1. Проверьте логи PM2
pm2 logs tashi-ani --lines 50

# 2. Проверьте, что приложение работает
curl -I https://tashi-ani.ru

# 3. Проверьте, что подозрительные запросы блокируются
# Попробуйте запросить файл с подозрительным именем
curl "https://tashi-ani.ru/api/uploads/objects/1/../../../etc/passwd"
# Должен вернуть ошибку 400 или 403
```
